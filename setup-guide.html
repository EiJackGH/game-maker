Quick Start

Blocks is a zero-setup, browser-native game engine and visual IDE. You do not need to install Node.js, build tools, or browser extensions to start creating.

1. Open Studio

Launch index.html in any standard modern web browser.

2. Load Template

Pick a starter template like Platformer or Maze Raider from the top bar.

3. Paint & Play

Switch to Paint mode to draw tiles, then click Play Mode to test physics in real time.

2

System & Browser Requirements

Blocks relies on modern web standard features including HTML5 Canvas, Web Audio API, LocalStorage, and ES6 JavaScript. Ensure JavaScript is enabled in your browser settings.

Google Chrome & Microsoft Edge

Navigate to Settings > Privacy and security > Site Settings > JavaScript. Ensure "Sites can use JavaScript" is toggled ON.

Mozilla Firefox

Type about:config in your address bar, search for javascript.enabled, and verify it is set to true.

Apple Safari

Open Safari Settings > Security tab > Ensure the checkbox for "Enable JavaScript" is checked.

Mobile & Touch Controls

Mobile Mode enables touch virtual D-Pad and Jump controls automatically on touchscreen devices.

Having trouble loading JavaScript? Check our dedicated NoScript Troubleshooting Page.

Studio Interface Layout

The editor workspace is organized into three main regions designed for smooth, rapid level creation:

Left Panel: Drawing Tools & Palette

Contains the active tool selector (Brush, Eraser, Fill Bucket, Inspect) alongside categorized tiles: Solids, Hazards, Interactives, Characters, and Custom Blocks.

Center Workspace: Canvas Grid

Interactive 2D level canvas with zoom/pan controls (Shift + Drag to pan, mouse wheel to zoom). Switch between Design Mode and Play Mode instantly.

Right Panel: Properties, Logic, AI & Files

  • Properties: Configure block collision, damage power, score values, and base colors.
  • Scripts: Attach visual event rules and write custom JavaScript functions.
  • Sprites: Choose emojis and palette base colors for blocks and actors.
  • AI Copilot: Generate custom level layouts and scripts using natural language prompts.
  • Files: Save, export, import, and manage multiple level projects locally.

Visual Logic & Custom Scripting

Blocks provides both visual no-code triggers and full JavaScript runtime hooks for power users.

Available Script Runtime API Globals
player.vy = -12; Modifies player vertical velocity (e.g., super jump bounce).
game.addCoins(5); Awards bonus score coins to the active game state.
sound.play('coin'); Triggers built-in Web Audio retro synthesizer SFX ('jump', 'coin', 'hit', 'win').
game.gravity = 0; Dynamically adjusts gravity or physics variables.
const VALUE = 100; Defines a custom variable or constant construct for logic scripting.
Static Code Analysis & Validation

The studio includes a real-time static code analysis engine that flags syntax errors, prohibited browser globals (such as window or document), infinite loop constructs, and unrecognized top-level variables before running.

Exporting Games for GitHub Pages

Once your game design is complete, you can export a self-contained web bundle ready for hosting on GitHub Pages or any static web web server.

Step 1: Click "Build Pages Dist"

In the top bar or right sidebar, click Build Pages Dist to download a single self-contained .html file containing your entire level grid, sprite graphics, physics, and custom code.

Step 2: Commit to GitHub

Add the exported HTML file to your repository root (e.g. as index.html) and push to your main branch.

Step 3: Enable GitHub Pages

In your GitHub Repository Settings > Pages, set the source to deploy from the main branch. Your game will be live instantly!

Frequently Asked Questions

Where are my level designs saved?

Saved level projects are stored locally inside your browser's persistent localStorage. You can also export `.json` file backups anytime from the Files panel.

Can I switch genres mid-level?

Yes! Use the Genre selector in the top bar to toggle between Platformer (gravity jump physics) and Top-Down (RPG/maze exploration).

Does exported game bundle need external servers?

No. Exported web bundles are 100% self-contained HTML files that include all engine code, tile rendering, sound synthesis, and logic offline.
